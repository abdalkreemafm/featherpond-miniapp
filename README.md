# بركة الريش — Telegram Mini App

لعبة إدارة بركة عربية مستقلة برسوم أصلية: إطعام البط، جمع البيض، دمج البيض المتساوي، فقس أنواع جديدة، مهام يومية، ولوحة ترتيب وعروض تعاون غير متزامنة بين اللاعبين. تستلهم دورة لعب عامة فقط؛ لا تستخدم شيفرة Duck My Duck أو علامتها أو رسومها. لا توجد مدفوعات أو رموز أو أصول مشفّرة.

العميل مبني بـ Godot Web، ويتصل بخادم Node.js مستقل وقاعدة SQLite ذاتية الاستضافة. يرسل العميل `Telegram.WebApp.initData` الخام؛ يتحقق الخادم من توقيع Telegram باستخدام رمز البوت ولا يثق بـ `initDataUnsafe` أو معرف اللاعب المرسل من العميل. إذا لم توجد جلسة Telegram أو تعذّر الخادم، تبقى دورة اللعب الأساسية متاحة محلياً مع حفظ في `user://` على الجهاز.

## المتطلبات

- Godot 4.7 مع قوالب تصدير Web المطابقة لنسخته لبناء العميل.
- Node.js 22.13 أو أحدث للخادم؛ لا توجد حزم npm خارجية للخادم.
- خادمك يدعم Docker Compose، أو تشغيل Node مباشرة مع قرص دائم لملف SQLite.
- نطاق HTTPS عام مضبوط كتطبيق Mini App في إعدادات البوت. اللعبة والخادم مهيآن افتراضياً للعمل من الأصل (origin) نفسه.

## 1. بناء ملفات Telegram Web

من جذر المشروع شغّل Godot CLI الذي يحتوي قوالب Web:

```sh
npm run export
```

يجب أن يكتمل التصدير من دون أخطاء، وأن ينتج `index.html` وملفات Godot `.wasm` و`.pck` في `dist/standalone/`. لا ترفع مجلد `.godot/`؛ `dist/` ناتج بناء ويمكن إنشاؤه مجدداً.

تحقق من اللعبة والخادم بعد البناء:

```sh
npm run verify
```

## 2. إعداد BotFather والنطاق

1. أنشئ بوتاً أو استخدم بوتك، ثم عيّن رابط HTTPS العام للعبة كتطبيق Mini App (رابط التطبيق الرئيسي أو رابط التطبيق القصير) عبر BotFather.
2. أضف سجل DNS وشهادة HTTPS لنطاق اللعبة قبل فتحه داخل Telegram.
3. سجّل اسم البوت واسم Mini App القصير. يلزم الاثنان لتكوين رابط دعوة يعمل بصيغة `https://t.me/<bot>/<app>?startapp=pond`.
4. احتفظ برمز البوت لاستخدامه على الخادم فقط؛ لا ترسله للعبة ولا إلى مستودع Git.

## 3. تشغيل Docker على استضافتك

```sh
cd deploy
cp .env.example .env
chmod 600 .env
```

عدّل `deploy/.env` على الخادم:

- `BOT_TOKEN`: رمز البوت السري من BotFather.
- `BOT_USERNAME`: اسم البوت من دون `@`.
- `MINI_APP_SHORT_NAME`: الاسم القصير المضبوط للتطبيق.
- `WEB_ORIGINS`: أصل HTTPS الدقيق، مثل `https://pond.example.com` ومن دون `/` في النهاية.
- `HOST_PORT`: منفذ localhost الذي سيصل إليه Nginx (افتراضياً 3000).

بعد تصدير العميل:

```sh
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:3000/api/health
```

أضف مقطع `nginx-location.conf` إلى خادم HTTPS الحالي، أو استخدم reverse proxy لديك، ووجّه النطاق إلى `127.0.0.1:3000`. لا تفتح منفذ التطبيق للعامة مباشرة إذا كان TLS ينتهي عند Nginx. بيانات SQLite محفوظة في Docker volume اسمه `featherpond_data`، ولذلك تبقى عند إعادة إنشاء الحاوية.

للتحديث: أعد تصدير Godot ثم أعد بناء صورة الحاوية باستخدام `docker compose up -d --build` من مجلد `deploy`.

## تشغيل Node مباشرة بدلاً من Docker

بعد بناء الملفات، يمكن تشغيل الخادم من مجلد `server`:

```sh
cd server
BOT_TOKEN='...' \
BOT_USERNAME='YourBotUsername' \
MINI_APP_SHORT_NAME='play' \
WEB_ORIGINS='https://pond.example.com' \
STATIC_DIR='../dist/standalone' \
DATA_DIR='../data' \
HOST='127.0.0.1' PORT='3000' \
node server.mjs
```

اجعل `DATA_DIR` على قرص دائم وخلف HTTPS reverse proxy. إذا وضعت API على نطاق منفصل، اضبط `content` في وسم `meta[name="pond-api-base"]` داخل `web/loading.html` على أصل API وأعد التصدير؛ ثم أضف أصل اللعبة إلى `WEB_ORIGINS`.

## واجهة الخادم

- `GET /api/health`: فحص خدمة غير حساس.
- `GET /api/state`: تحميل اللاعب والقطيع والبيض والمهام والعروض ولوحة الصدارة بعد تحقق Telegram.
- `POST /api/action`: تنفيذ إجراء من القائمة المسموحة؛ الطلب يستخدم `requestId` فريداً لتجنب تكرار المكافأة عند إعادة المحاولة.

الخادم وحده يغيّر العملات والموارد والنقاط والبيض والعروض. توجد قيود للمخزون، وحدود للعروض، وانتهاء للعروض، ومهام يومية. التزاوج هنا تعاون اجتماعي غير متزامن وليس مباراة حية بين لاعبين.

## الخصوصية والتشغيل

يخزن SQLite معرّف Telegram الرقمي اللازم لربط التقدم، اسماً مستعاراً مولّداً، وبيانات اللعب والنتائج والعروض. لا يخزن الخادم `initData` الخام أو الاسم الأول أو اسم مستخدم Telegram. أضف سياسة خصوصية واحتفظ بنسخ احتياطية آمنة لقرص البيانات بحسب قوانين منطقتك. لا تضع `.env` أو رمز البوت أو ملفات قاعدة البيانات في Git أو في ملفات العميل.

## محتويات المشروع

- `scripts/pond_game.gd`: شاشات البركة والحاضنة والأصدقاء والمهام، والحفظ المحلي ووصلة Telegram/API.
- `server/server.mjs`: تحقق HMAC من Telegram، API، منطق اللعب، وSQLite.
- `assets/pond/runtime_final/`: بطات وبيض مولّدة ومهيأة للعرض.
- `assets/share/favicon.png`: أيقونة اللعبة.
- `gameplay-research.md`: ملاحظات نطاق اللعب وروابط المصدر العام ووثائق Telegram.
